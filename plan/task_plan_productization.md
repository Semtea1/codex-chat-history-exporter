# Task Plan: 聊天记录导出器产品化设计

## Goal
把当前命令行导出脚本升级为可产品化的方案，明确共享核心、VS Code 插件优先、Codex 插件二期的结构与导出模式设计。

## Phases
- [x] Phase 1: 明确产品方向
- [x] Phase 2: 固化需求与约束
- [x] Phase 3: 形成规格草案
- [x] Phase 4: 进入实现拆分

## Key Questions
1. 导出内容的“可见/不可见”边界如何抽象成稳定的勾选模型？
2. VS Code 插件与 Codex 插件如何共用同一套导出核心？
3. 每会话固定文件夹前提下，单文档、多文档、附录式导出如何统一成一套可配置输出策略？

## Decisions Made
- 共享导出核心作为唯一真相源，前端形态只负责 UI 与入口。
- 产品首期优先 VS Code 插件，覆盖本地 VS Code 与 Remote-SSH 使用场景。
- Codex 插件作为二期入口层复用共享核心，不重复实现导出逻辑。
- 每条会话固定导出到一个文件夹，文档组织方式发生在该文件夹内部。
- “聊天正文与图片”也是可单独勾选的导出分组。
- 导出结果根目录由用户在导出时选择，也可由 profile 提供默认值。
