# 聊天记录导出器产品规格草案

## 1. 产品目标

本产品用于把 Codex 会话导出为适合阅读、审计与取证的高质量文档，覆盖：

- 聊天正文导出
- 图片原位恢复
- 聊天正文与图片可单独勾选是否导出
- 隐藏上下文按类别可选导出
- 完整工具轨迹导出
- 单条与多条会话批量导出
- 每会话固定一个导出文件夹
- 每会话文件夹内支持单文档与多文档两种组织方式
- 用户自选导出结果根目录

首期交付形态为：

- **共享导出核心**
- **VS Code 插件前端**

二期交付形态为：

- **Codex 插件前端**

## 2. 目标用户

### 2.1 主用户
- 需要整理个人聊天记录的用户
- 需要复盘模型行为的用户
- 需要保留 prompt / context / tool trace 证据链的用户

### 2.2 高价值场景
- 本地 Codex Desktop 会话归档
- VS Code 中的 Codex 使用记录导出
- VS Code Remote-SSH 场景下的远程开发会话归档
- 针对复杂排障或研究工作流的“完整取证导出”

## 3. 产品形态与路线

## 3.1 方案选项

### 方案 A：先做独立 exe
- 优点：入口独立，不依赖编辑器
- 缺点：需要额外打包、分发、配置与升级机制
- 结论：不作为首期优先

### 方案 B：先做 VS Code 插件
- 优点：最贴近当前真实使用场景，容易做会话列表、多选与导出面板
- 优点：可同时覆盖本地 VS Code 与 Remote-SSH 使用入口
- 缺点：Codex Desktop 内仍缺一个原生入口
- 结论：**首期推荐方案**

### 方案 C：同时做 VS Code 插件 + Codex 插件
- 优点：双入口完整
- 缺点：首期开发面更大，调试复杂度更高
- 结论：作为二期扩展，不建议首期并行

## 3.2 推荐路线

### Phase 1
- 提炼共享导出核心
- 增补导出模型、隐藏内容分类、排版引擎
- 提供 VS Code 插件 UI

### Phase 2
- 为 Codex 客户端做入口层插件
- 复用同一导出核心与导出配置

### Phase 3
- 如有需要，补充独立 exe 包装

## 4. 数据源与兼容性假设

### 4.1 当前已验证事实
- 当前会话真相源是本地 `C:\Users\20312\.codex\sessions`
- 现有导出脚本已验证可区分：
  - `desktop`
  - `vscode`
  - `cli`

### 4.2 关于 Remote-SSH 的产品判断
- **基于当前本机证据推断**：你在本地 VS Code 中通过 SSH 连接 Ubuntu 服务器时，若 Codex 会话仍同步写入本地 `.codex/sessions`，那么**本地 VS Code 插件即可覆盖该场景**
- 因此：
  - **不是必须先做两个完全独立的插件**
  - **VS Code 插件优先是成立的**
  - Codex 插件更多是“额外客户端入口”，不是覆盖 Remote-SSH 的唯一手段

## 5. 导出内容分类模型

产品中所有内容按“**1 个正文分组 + 6 个上下文分组**”建模，全部支持勾选：

### 5.0 聊天正文与图片 (`user_message`, `response_item.message`, `input_image`)
- 内容：用户消息、助手消息、图片原位恢复
- 用途：形成用户真正用于阅读和整理的聊天正文
- 可见性：客户端可见
- 补充选项：
  - 是否带消息级时间戳
  - 是否只导出指定日期 / 时间区间内的正文消息
  - 当正文按时间区间裁切时，是否连带保留同时间段关联的工具轨迹

### 5.1 会话基础信息 (`session_meta`)
- 内容：session id、originator、source、时间、cwd、原始日志路径
- 用途：定位会话与来源
- 可见性：客户端不可见

### 5.2 系统运行上下文 (`permissions instructions`, `app-context`)
- 内容：权限、sandbox、automation、review、archiving、git 等运行规则
- 用途：解释模型运行边界
- 可见性：客户端不可见

### 5.3 Memory 上下文 (`memory`, `oai-mem-citation`)
- 内容：用户偏好、历史任务摘要、memory citation
- 用途：解释模型继承的长期偏好与历史判断
- 可见性：客户端不可见

### 5.4 工作区规则上下文 (`AGENTS.md`, `INSTRUCTIONS`, `environment_context`)
- 内容：项目规则、skills 列表、cwd、shell、日期、时区
- 用途：解释模型为何遵循某些工作流或约束
- 可见性：客户端不可见

### 5.5 协作控制上下文 (`collaboration_mode`, `request_user_input availability`)
- 内容：交互模式、工具可用性
- 用途：解释对话层行为边界
- 可见性：客户端不可见

### 5.6 工具执行轨迹 (`function_call`, `function_call_output`, `custom_tool_call`, `web_search_call`)
- 内容：工具调用参数、工具输出、退出码、耗时
- 用途：完整复盘模型实际执行过程
- 可见性：客户端半可见

## 6. UI 展示规则

## 6.1 分类勾选项命名

UI 中每一类都显示为：

- **中文标签（原始字段名）**

示例：

- 聊天正文与图片 (`user_message`, `response_item.message`, `input_image`)
- 会话基础信息 (`session_meta`)
- 系统运行上下文 (`permissions instructions`, `app-context`)
- Memory 上下文 (`memory`, `oai-mem-citation`)
- 工作区规则上下文 (`AGENTS.md`, `INSTRUCTIONS`, `environment_context`)
- 协作控制上下文 (`collaboration_mode`, `request_user_input availability`)
- 工具执行轨迹 (`function_call`, `function_call_output`, `custom_tool_call`, `web_search_call`)

## 6.2 分类说明

每类旁边均带说明按钮或 hover 卡片，说明：

- 这类内容是什么
- 为什么客户端通常看不到
- 导出它的用途是什么
- 它会影响文档长度和可读性

## 7. 默认导出模式

## 7.1 阅读版
- 勾选：
  - 聊天正文与图片
- 默认关闭：
  - 6 类隐藏内容
- 适用：个人整理、知识归档、二次阅读

## 7.2 审计版
- 勾选：
  - 聊天正文与图片
  - 工具执行轨迹
  - 会话基础信息
- 默认关闭其余隐藏上下文
- 适用：复盘模型做了什么

## 7.3 取证版
- 勾选：
  - 聊天正文与图片
  - 全部 6 类隐藏内容
  - 完整工具轨迹
- 适用：排障、合规、研究留档

## 8. 自定义导出模式

用户可以：

- 基于任一默认模式复制
- 自行勾选“正文分组 + 6 类上下文分组”
- 保存为自定义 profile
- 重命名、更新、删除 profile

### 建议配置结构
- `profile_id`
- `profile_name`
- `included_sections[]`
- `document_layout`
- `hidden_content_layout`
- `tool_trace_level`
- `include_message_timestamps`
- `message_time_range`
- `linked_trace_time_behavior`
- `description`

## 9. 导出组织方式

## 9.1 会话容器规则
- **每条会话固定导出到一个独立文件夹**
- 多会话导出时：
  - 导出根目录下生成多个会话文件夹
  - 可选生成总索引 `index.md`

示例：

```text
export-root/
  index.md
  session-A/
    transcript.md
    hidden-context.md
    assets/
  session-B/
    transcript.md
    tool-trace.md
    assets/
```

## 9.2 会话文件夹内的文档组织方式
- **单文档**：所选内容合并到一个主文档
- **多文档**：按正文 / 隐藏上下文 / 工具轨迹拆成多个文档

## 9.3 隐藏内容组织方式
- **内联**：直接混排在主文档对应位置
- **附录**：正文后追加隐藏上下文附录
- **拆分**：正文与隐藏内容分成多个文档

## 9.4 推荐默认值
- 阅读版：每会话一个文件夹，默认 `transcript.md`
- 审计版：每会话一个文件夹，默认 `transcript.md` + 可折叠工具轨迹附录
- 取证版：每会话一个文件夹，默认 `transcript.md` + `hidden-context.md` + `tool-trace.md`

## 10. 会话选择能力

## 10.1 选择方式
- 搜索会话标题
- 按来源筛选：
  - desktop
  - vscode
  - cli
- 按时间筛选
- 单选
- 多选
- 全选当前筛选结果

## 10.2 展示字段
- 标题
- 时间
- 来源
- cwd
- 会话 ID
- 预估导出体积

## 10.3 正文时间裁切
- 用户可选择只导出某一日期范围内的正文
- 用户可选择只导出某一具体时间区间内的正文
- 时间裁切默认只作用于“聊天正文与图片”分组
- 可选高级行为：
  - 仅裁切正文
  - 正文与关联工具轨迹一并裁切

## 11. 排版要求

## 11.1 视觉目标
- 聊天正文易读
- 图片原位自然
- 隐藏内容不抢正文注意力
- 工具轨迹可折叠

## 11.2 推荐文档结构
- 标题
- 元信息摘要
- 正文 transcript
- 可选附录
- 资源目录

## 11.3 呈现建议
- 正文使用清晰段落
- 图片在消息原位插入
- 正文可选显示消息时间戳
- 隐藏内容用 callout / details / sidecar block
- 每个隐藏块都带“分类说明”
- 工具轨迹至少支持“摘要/完整”两级展开

## 11.4 输出目录选择
- 用户可在导出前自行选择导出结果根目录
- 多会话导出时，所有会话文件夹都落在该根目录下
- profile 可保存“默认导出目录”，也可在每次导出时临时覆盖

## 12. 架构设计

## 12.1 共享核心
- 会话扫描器
- 分类器
- 图片提取器
- 导出模式解释器
- 排版引擎
- 输出写入器

## 12.2 VS Code 插件
- 会话列表视图
- 导出模式管理页
- 导出向导
- 导出目录选择器
- 导出结果打开入口

## 12.3 Codex 插件（二期）
- 读取同一配置
- 调用同一核心
- 提供客户端内“导出当前会话 / 批量导出”入口

## 13. 首期实现边界

首期建议只做：

- 共享核心重构
- 正文分组 + 6 类上下文模型
- 3 种默认模式
- 自定义模式保存
- 单会话 / 多会话导出
- 每会话文件夹 + 单文档 / 多文档导出
- 导出目录选择
- 正文时间戳与时间区间裁切
- VS Code 插件 UI

暂不首期做：

- exe 打包
- 云同步 profile
- 在线分享页面

## 15. 当前建议结论

- 方向：**共享核心 + VS Code 插件优先 + Codex 插件二期**
- 默认模式：**阅读版 / 审计版 / 取证版**
- 配置粒度：**正文分组 + 6 类上下文全可勾选**
- 命名方式：**中文标签（原始字段名）**
- 输出组织：**每会话固定文件夹，文件夹内支持单文档 / 多文档 / 附录 / 拆分**
